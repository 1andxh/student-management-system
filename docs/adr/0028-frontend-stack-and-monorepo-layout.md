# 0028. Frontend stack and monorepo layout

## Status
Accepted. Stack and layout from F1; auth client and routing from F3.

## Context
A separate frontend already existed outside this repo. Solomon was unhappy with it on two counts: it looked generic, and its flows didn't match how each role actually uses the system. He chose to rebuild it inside this repo, designed from the backend's real shape (role-specific "me" endpoints, one-time secrets, distinct 409 conflict kinds) rather than as a browser over every resource.

The backend is a typed REST API. Nearly every screen requires a login, the app has four roles and needs no SEO, and auth uses an in-memory access token plus an HttpOnly refresh cookie (ADR 0027).

## Decision
- **Layout: the backend stays at the repo root, and the frontend lives in `web/`.** Moving the backend into `apps/api` would have meant rewriting the Dockerfile, CI, alembic paths and the file references throughout ADRs 0001–0027. That is a refactor of its own, with nothing to show for it in the frontend. `web/` is self-contained: its own `package.json`, lockfile, `.gitignore` and CI job.
- **A Vite + React + TypeScript SPA, not a meta-framework.** There's nothing to server-render and no SEO to win. An SPA keeps the client/server boundary explicit: one HTTP API, one client. That boundary is part of what this project exists to practice. SvelteKit and Next.js were considered. Both add a second server process. Their main draw here, a backend-for-frontend that holds tokens server-side, was made unnecessary by ADR 0027's cookie.
- **TanStack Router (file-based) and TanStack Query.** The router gives typed route params and *typed search params*, so pagination and filters live in the URL: shareable, survive a reload, and the back button works. Its `beforeLoad` hooks give per-role route guards. Query is the server-state cache, so "data from the API" is never copied into component state by hand, and mutations invalidate what they change.
- **API types are generated from the backend's OpenAPI schema** (`openapi-typescript` + `openapi-fetch`, `web/src/lib/api.ts`). `sms.scripts.dump_openapi` prints the schema directly from the FastAPI app object, so generation needs no running server: building the app only constructs the SQLAlchemy engine, which connects lazily. The generated `src/lib/api-schema.d.ts` is committed, and CI regenerates and diffs it. A backend change not followed by `npm run gen:api` fails CI instead of leaving the frontend type-checking against an API that no longer exists. `src/routeTree.gen.ts` (generated by the router plugin) is committed and checked the same way, because `tsc` runs before any build would regenerate it.
- **Tailwind v4 for styling.** Design tokens will live in `@theme` (ADR 0029, Stage F2), so components use semantic names (`bg-surface`, `text-ink-3`) rather than raw values.
- **Libraries are added in the stage that first uses them, not up front.** React Aria Components arrives in F2b (accessible primitives), and react-hook-form + zod in F3 (login form). A dependency nothing imports yet is weight without a test. In F3, react-hook-form + zod turned out to be unnecessary. React Aria's `Form` handles required and format validation through each field's `validate`, and shows errors through the fields' existing `FieldError`. Server errors for sign-in are uniform by design, so there was nothing field-level to map. They stay out until a form needs them. Playwright came earlier than planned, in F2a, to screenshot the styleguide in both themes and at phone width. It drives the system Chrome (`channel: "chrome"`) rather than downloading its own browser. Fonts (`@fontsource`) came in with F2a too (ADR 0029).
- **npm, not pnpm.** The plan said pnpm, but it wasn't installed, and Node 26 no longer bundles corepack to enable it. For a single package, pnpm's advantages (workspaces, a shared content store) don't apply, so npm costs nothing here. Revisit this if `web/` ever splits into several packages.
- **TypeScript pinned to 5.9.3, not 7.x.** TypeScript 7 (the Go port) is `latest`, but typescript-eslint supports `<6.1` and openapi-typescript declares `^5.x`. 5.9.3 is the newest release inside both ranges. All dependency versions are pinned exactly (`--save-exact`), on top of the lockfile.
- **Dev server is pinned to `127.0.0.1:5173` with `--strictPort`.** The API's CORS allowlist and the refresh cookie depend on that exact origin. Without `--strictPort`, a busy port makes Vite quietly move to 5174, and every API call then fails with an opaque CORS error.

### Auth client and routing (F3)
- **The access token lives in memory only** (`web/src/lib/auth/session.ts`). The refresh token is the HttpOnly cookie (ADR 0027), so a page reload restores the session with one `POST /auth/refresh` at boot.
- **Refresh is single-flight within a tab and serialized across tabs with `navigator.locks`.** The backend rotates the cookie on every refresh. Without single-flight, several requests hitting 401 together would each refresh and all but one would fail. Without the lock, two tabs would race the same cookie. `session.test.ts` reproduces both races against a fake that implements the backend's exact rotation rule.
- **The API middleware** (`web/src/lib/auth/middleware.ts`) attaches the token. On a 401 it refreshes and retries the request once, from a copy of the request taken before sending, because a request body can only be read once. It never touches `/auth/login`, `-pin`, `/refresh` or `/logout`, where a 401 means wrong credentials. Only a 401 from refresh ends the session; a network failure is not a logout.
- **Every way a session ends clears the TanStack Query cache:** logout, expiry, and logout in another tab via `BroadcastChannel`. The next person on a shared computer must not see the previous person's cached data.
- **Hardened after the F3 security review (ADR 0031 lists every finding):**
  - **Logout checks the server's answer.** A 429/403/500 doesn't throw, and only the server can clear the HttpOnly cookie. So an unconfirmed logout warns the user ("Sign-out didn't reach the server… close every browser window") instead of looking safely signed out.
  - **The session records whose token it holds** (the JWT `sub`). A refreshed token for a different user, meaning another tab signed in as someone else and the shared cookie changed hands, ends this tab's session instead of carrying on as that person. Sign-ins are broadcast to other tabs too.
  - **`clear()` advances an epoch counter,** so a refresh still in flight when the session ends discards its late answer instead of restoring the previous user's token.
  - **`safeRedirect` re-validates its output.** `/..//evil.example` passes the origin check but normalizes to the protocol-relative `//evil.example`.
  - **Ending a session on purpose (`signedOut`) drops `?redirect=`,** so the next person doesn't land on the previous person's last page. An *expired* session keeps it, so the same user can carry on.
  - **Module-level state is reset between tests,** like the backend's rate limiter: the toast queue outlives renders, and error toasts never time out, so one test's toast leaked into the next until `clearToasts` ran after each test.
- **Routing:**
  - Each role has its own area: `/admin` (admin and super admin), `/teacher` and `/student`.
  - Each area's layout route guards with `requireRole` in `beforeLoad`. Signed out goes to `/login?redirect=…`; the wrong role goes to that user's own home. **The guards are navigation, not security.** The API enforces every permission.
  - The post-login redirect passes through `safeRedirect`, which uses the URL parser, so `//evil.example`, `/\evil.example` and tab-smuggled variants are refused the way a browser would resolve them.
- **The router waits for the boot refresh.** `App` renders a spinner until the session is known, and calls `router.invalidate()` on every session change, but never while loading. Doing it while loading ran every guard against an undefined context on every page load. That bug was silent on screen and caught in the browser console.
- **A page missing inside an area renders inside that area's shell,** from the `$page` route, rather than through `notFoundComponent`. TanStack's `notFoundComponent` on a layout route replaces the layout, which would take the sidebar and Log out with it.
- **The styleguide is development-only:** its route throws `notFound()` unless `import.meta.env.DEV`.
- **Rapid reloads used to sign users out.** The fix is backend-side: the grace window in ADR 0031.

## Consequences
- Anyone changing a backend route or schema must run `npm run gen:api` and commit the result; CI enforces it. The web CI job therefore installs both Node and the backend's Python dependencies.
- **Known, accepted audit finding:** a moderate ReDoS advisory in `minimatch` (GHSA-g3hv-75wg-m249), reached only through ESLint's dev tooling, which matches globs this repo writes. Nothing in the built app depends on it. The suggested fix downgrades ESLint by a major version, which is not worth it. Re-check when ESLint updates.
- Upgrading to TypeScript 7 waits on typescript-eslint and openapi-typescript supporting it.
- **Unverified: Safari.** It may refuse the Secure refresh cookie on `http://127.0.0.1` (ADR 0027). Chrome is verified; Safari and Firefox are not yet.
- The `web/` frontend is not containerized. It runs on the host via `npm run dev`, against the API in Docker or `uv run uvicorn`. A production build (static files behind nginx) is deferred until there's somewhere to deploy.
