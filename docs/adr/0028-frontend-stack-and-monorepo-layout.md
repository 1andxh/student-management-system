# 0028. Frontend stack and monorepo layout

## Status
Accepted (stack and layout). The auth-client section is added in frontend Stage F3.

## Context
A separate frontend already existed outside this repo. Solomon was unhappy with it on two counts: it looked generic, and its flows didn't match how each role actually uses the system. He chose to rebuild it inside this repo, designed from the backend's real shape (role-specific "me" endpoints, one-time secrets, distinct 409 conflict kinds) rather than as a browser over every resource.

The backend is a typed REST API. Nearly every screen requires a login, the app has four roles and needs no SEO, and auth uses an in-memory access token plus an HttpOnly refresh cookie (ADR 0027).

## Decision
- **Layout: the backend stays at the repo root, and the frontend lives in `web/`.** Moving the backend into `apps/api` would have meant rewriting the Dockerfile, CI, alembic paths and the file references throughout ADRs 0001–0027. That is a refactor of its own, with nothing to show for it in the frontend. `web/` is self-contained: its own `package.json`, lockfile, `.gitignore` and CI job.
- **A Vite + React + TypeScript SPA, not a meta-framework.** There's nothing to server-render and no SEO to win. An SPA keeps the client/server boundary explicit: one HTTP API, one client. That boundary is part of what this project exists to practice. SvelteKit and Next.js were considered. Both add a second server process. Their main draw here, a backend-for-frontend that holds tokens server-side, was made unnecessary by ADR 0027's cookie.
- **TanStack Router (file-based) and TanStack Query.** The router gives typed route params and *typed search params*, so pagination and filters live in the URL: shareable, survive a reload, and the back button works. Its `beforeLoad` hooks give per-role route guards. Query is the server-state cache, so "data from the API" is never copied into component state by hand, and mutations invalidate what they change.
- **API types are generated from the backend's OpenAPI schema** (`openapi-typescript` + `openapi-fetch`, `web/src/lib/api.ts`). `sms.scripts.dump_openapi` prints the schema directly from the FastAPI app object, so generation needs no running server: building the app only constructs the SQLAlchemy engine, which connects lazily. The generated `src/lib/api-schema.d.ts` is committed, and CI regenerates and diffs it. A backend change not followed by `npm run gen:api` fails CI instead of leaving the frontend type-checking against an API that no longer exists. `src/routeTree.gen.ts` (generated by the router plugin) is committed and checked the same way, because `tsc` runs before any build would regenerate it.
- **Tailwind v4 for styling.** Design tokens will live in `@theme` (ADR 0029, Stage F2), so components use semantic names (`bg-surface`, `text-ink-3`) rather than raw values.
- **Libraries are added in the stage that first uses them, not up front.** React Aria Components arrives in F2b (accessible primitives), and react-hook-form + zod in F3 (login form). A dependency nothing imports yet is weight without a test. Playwright came earlier than planned, in F2a, to screenshot the styleguide in both themes and at phone width. It drives the system Chrome (`channel: "chrome"`) rather than downloading its own browser. Fonts (`@fontsource`) came in with F2a too (ADR 0029).
- **npm, not pnpm.** The plan said pnpm, but it wasn't installed, and Node 26 no longer bundles corepack to enable it. For a single package, pnpm's advantages (workspaces, a shared content store) don't apply, so npm costs nothing here. Revisit this if `web/` ever splits into several packages.
- **TypeScript pinned to 5.9.3, not 7.x.** TypeScript 7 (the Go port) is `latest`, but typescript-eslint supports `<6.1` and openapi-typescript declares `^5.x`. 5.9.3 is the newest release inside both ranges. All dependency versions are pinned exactly (`--save-exact`), on top of the lockfile.
- **Dev server is pinned to `127.0.0.1:5173` with `--strictPort`.** The API's CORS allowlist and the refresh cookie depend on that exact origin. Without `--strictPort`, a busy port makes Vite quietly move to 5174, and every API call then fails with an opaque CORS error.

## Consequences
- Anyone changing a backend route or schema must run `npm run gen:api` and commit the result; CI enforces it. The web CI job therefore installs both Node and the backend's Python dependencies.
- **Known, accepted audit finding:** a moderate ReDoS advisory in `minimatch` (GHSA-g3hv-75wg-m249), reached only through ESLint's dev tooling, which matches globs this repo writes. Nothing in the built app depends on it. The suggested fix downgrades ESLint by a major version, which is not worth it. Re-check when ESLint updates.
- Upgrading to TypeScript 7 waits on typescript-eslint and openapi-typescript supporting it.
- The `web/` frontend is not containerized. It runs on the host via `npm run dev`, against the API in Docker or `uv run uvicorn`. A production build (static files behind nginx) is deferred until there's somewhere to deploy.
